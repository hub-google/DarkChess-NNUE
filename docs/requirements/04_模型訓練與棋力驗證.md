# 04. 模型訓練與棋力驗證

## 一、 持續進化迴圈 (Continuous Evolution Loop)
系統將自動執行以下無限迴圈，實現 AI 棋力的持續成長：
1.  **Phase 1: 數據生成 (Self-Play)**：目前的「冠軍模型」與自己進行對戰，記錄盤面狀態與最終勝負結果。中央主機會監控模型升級的停滯期，若連續數日未能產生新冠軍，將自動下發指令提升前端 Worker 的 **最大思考深度 (MAX_SEARCH_DEPTH)**，強迫 AI 進行更深層的推演以產生高品質的破局資料。
2.  **Phase 2: 模型訓練 (Training)**：在中央主機上使用 Phase 1 產生的新棋譜，透過梯度下降法更新 NNUE 的權重參數，產生「挑戰者模型」。
3.  **Phase 3: 鏡像驗證 (Validation)**：讓挑戰者模型與冠軍模型進行 SPRT 鏡像對決。
4.  **Phase 4: 晉升 (Promotion)**：若挑戰者獲勝，則取代冠軍模型，發布新權重，返回 Phase 1 繼續產生更高質量的棋譜。

## 二、 模型調教與訓練細節 (Training Pipeline)
中央主機將實施「日更進化 (Nightly Build)」機制，確保模型每天都在變強。
*   **觸發條件**：改為 **每日固定時間 (Daily Cron Job)** 進行 Fine-tuning。
*   **自動化經驗回放池 (Automated Experience Replay Buffer)**：為防止災難性遺忘，訓練資料不只限於「前一天的新對局」，而是自動維護一個**滑動窗口（永遠只保留最新的 50 萬局，約同 AlphaZero 的配置）**的資料池。訓練時從池中均勻採樣，確保新舊戰術並存，同時避免被早期的菜鳥棋譜拖累進度。
    *   **Hyperparameters (超參數)**：
        *   **Loss Function (TD-Learning)**：不純依賴最終絕對勝負，改為 `Target = 0.5 * 最終勝負 + 0.5 * 該步搜尋樹根節點評估值`。讓先前的深思熟慮來平滑掉極端的運氣雜訊，避免梯度劇烈震盪。
        *   **Optimizer**：AdamW。
        *   **動態學習率 (Dynamic LR)**：不再採用死板的世代遞減，而是交由下方的「全自動自適應調校引擎」監控並動態指派。
    *   **Weight Decay**：`1e-4`。
    *   **Batch Size**：目前安全預設 `1024`，可由 `BATCH_SIZE` 調整。
*   **Training Epochs**：目前預設 **3 Epochs**，可由 `TRAINING_EPOCHS` 調整；若零資料或零有效 batch，訓練必須失敗且禁止晉升。

## 三、 全自動自適應調校引擎 (Auto-Tuning State Machine)
為實現「零人工介入」進化到世界第一，中央訓練主機將監控「連續 SPRT 失敗次數」與「和局率」，自動切換以下三種訓練狀態：
1.  **狀態 A：快速進步期 (Fast Learning)**
    *   **觸發條件**：模型頻繁獲勝，幾乎每次訓練都能產生新冠軍。
    *   **策略**：高 LR (`5e-4`)、適度探索溫度 (`1.0`)、較小的資料窗口 (最新 20 萬局)。給予較寬鬆的 SPRT Elo Bounds `[0, 15]` 鼓勵晉升。
2.  **狀態 B：停滯突破期 (Plateau / Local Optima)**
    *   **觸發條件**：連續 5 次 SPRT 失敗，模型卡在局部最佳解。
    *   **策略 (擾動機制)**：發動 LR 震盪重啟 (Warm Restarts) 彈回 `1e-4`。中央主機下令前端強制提高探索溫度至 `1.5~2.0` 以採集極端邊界數據。擴充資料窗口至 100 萬局，重新學習被遺忘的戰術。
3.  **狀態 C：終極收斂期 (World-Class Refinement)**
    *   **觸發條件**：和局率 > 70%，模型水準極高，勝負取決於微小失誤。
    *   **策略**：極微 LR (`<1e-6`)。前端探索溫度降至 `0.1~0` 採集純淨的高深度神仙打架棋譜。啟動極嚴苛的 SPRT 門檻 `[0, 5]`，寧可錯殺也不讓退步模型晉升。

## 四、 棋力驗證機制 (Pentanomial SPRT 配對檢定)
為解決暗棋高隨機性（即使同底盤仍會因後續翻牌不同產生極大雜訊）導致無法確認 AI 是否真實變強的痛點，導入國際象棋界常用的**配對賽計分 (Paired Match)**。

### 1. 配對鏡像對戰 (Paired AB Test)
*   **隨機底盤生成**：每次驗證隨機產生 **1,000 個** 固定亂數種子的合法隱藏底盤。為每一盤隨機分配一個「強制首步翻牌座標」。
*   **配對組合 (Pair)**：
    *   Game A：新模型(先) vs 舊模型(後) — 於底盤 Seed X，強制翻開座標 Y。
    *   Game B：舊模型(先) vs 新模型(後) — 於底盤 Seed X，強制翻開座標 Y。
*   **配對得分 (Pair Score)**：Game A 與 Game B 視為一組。計算新模型在該組的「總得分 (0.0 ~ 2.0)」，而非單場勝敗。這能完美抵銷先手優勢與大部分初始隨機雜訊。

### 2. 統計檢定 (Sequential Probability Ratio Test)
邊打邊驗證配對得分，累積達統計顯著即提前判定。
*   **Type I Error ($\alpha$)** / **Type II Error ($\beta$)**：0.05。
*   **動態 Elo bounds**：受狀態機控制。前期寬鬆 `[0, 15]` 加速通關，後期嚴苛 `[0, 5]` 保障血統。若檢定通過 (Accept H1)，發布新 `champion.nnue` 至 `/models/`。
