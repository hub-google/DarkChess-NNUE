# 01. 專案目標與架構總覽（實際實作）

> 更新日期：2026-10-22。本文件反映實際程式碼，而不是先前的 Cloudflare／瀏覽器叢集藍圖。

## 最終目標

在免費／低成本 CPU 環境建立可長期進化的高棋力台灣暗棋 AI，目標是參與國際強引擎實戰比較。**目前尚無任何世界第一或相對國際冠軍的棋力證明。**

## 真正投入運作的元件

1. **Python 正式搜尋引擎**：`src/training/board.py`、`search.py`，使用 4×8 Bitboard、Star1 機率分支、無隱藏資訊洩漏與 CPU 有界搜尋。
2. **NNUE Value**：`train.py`，498→256→32→1，從 Champion 續訓，不依賴 GPU。
3. **獨立實驗性 Policy**：`policy_train.py`，498→64→1024。Self-play 儲存從搜尋得出的稀疏教師走法機率 `pi`；Policy 可以在自我對弈探索階段與搜尋機率混合。**正式 SPRT 與瀏覽器引擎尚不使用此 Policy，不能宣稱已實現 AlphaGo Zero 完整演算法。**
4. **GitHub Actions CPU**：常態 `self_play.yml` 每六小時自動以 4 CPU Runner × 55 分鐘產生完整棋譜，另保留手動 15 Worker 加速模式；`train.yml` 每日 03:41 UTC 自動合併 HF 資料並以千局門檻保護 Value/Policy 訓練及配對 SPRT 晉升。
5. **資料儲存**：`hub-google/DarkChess-NNUE-Data` Hugging Face Dataset 的 staging 和 replay buffer；不得把未完成／無法重播的棋當成訓練樣本。
6. **GitHub Pages 網頁端**：獨立 TypeScript 人機對弈實驗介面，目前並非 Python 正式搜尋引擎。由手動部署 workflow 管理。

## 執行閉環

```text
Champion Value (+ optional promoted Policy)
    -> CPU bounded Star1 search + legal exploration
    -> complete real game replay (q/v/qd/pi/res)
    -> Hugging Face staging -> consolidated raw replay
    -> strict terminal replay validation + binary NPZ cache
    -> Value challenger + experimental Policy challenger
    -> paired SPRT on Value search
       reject/undecided -> keep champion
       accept H1        -> promote challenger and archive champion
```

## 目前已證實與未證實

- 2026-10-22：自動觸發 `self_play_trial.yml`，15 分鐘限時內產生兩局真實棋譜，且重播驗證兩局皆為合法終局；測試使用安全節點預算，不寫入 HF。
- `pipeline_smoke.yml` 通過 CPU-only 完整小型資料／Value／Policy 訓練與 SPRT 的連線驗收。Smoke 的 `UNDECIDED` 不構成 Challenger 棋力進步。
- 尚未完成：正式 15 Runner 高產量生產測試、正式 500k replay 資料恢復、長期政策模型棋力比較、Rust/C++ 高效搜尋替換、瀏覽器正式搜尋整合、國際引擎基準。

## 開發準則

1. 不可讓節點預算耗盡後自動取消預算，`depth=0` 只能用最終勝負學 Value，不能當 Star1 教師。
2. 一局必須完整且可重播後才保存；零產出必須讓 Worker 失敗，不能綠燈誤報。
3. Self-play 的 Policy 混合只在探索階段有效；實際棋力提升需同 CPU 時間的配對測試證明。
4. 不要自動打開原本手動的正式訓練 cron；驗收 workflow 可以在 code push 時自動執行。
5. 先確保正確性、每 CPU 小時完成棋局數、獨立對手 Elo，再擴張模型／算力。
