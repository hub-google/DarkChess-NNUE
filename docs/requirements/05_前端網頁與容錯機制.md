# 05. 前端網頁與容錯機制

## 一、 系統模組與分工架構

1.  **運算節點：Frontend Worker (GitHub Pages)**
    *   **極簡掛機介面**：顯示貢獻局數、NPS、當前版本。
    *   **Web Worker 多執行緒**：在背景執行緒編譯 WASM 榨乾 CPU。
    *   **自動同步大腦**：定時下載最新的 `champion.nnue` 進行熱更新。
2.  **中繼安全站：Edge Function (Cloudflare Workers)**
    *   不把 API Key 寫死在前端。每次上傳前先向中繼站請求 **Pre-signed URL**，再直傳 Bucket。
3.  **中央大腦：Training Node (本地 Python 訓練端)**
    *   非同步下載資料，進行 NNUE 訓練，並執行 SPRT 驗證，最後自動 Push 新權重檔。
4.  **人機對弈驗證介面：Playable Web UI (GitHub Pages)**
    *   **畫面佈局**：統一使用 **React + TailwindCSS + TypeScript** 開發，並具備 RWD 手機版支援。
    *   **棋盤與狀態區塊**：提供 4x8 視覺化對戰棋盤。旁邊需顯示即時「勝率預測條 (Eval Bar)」與「當前載入的模型版本」。
    *   **難度與時間控制面板**：下拉選單提供思考時間限制 (`1秒 (快棋)`、`5秒 (標準)`、`無限制 (最強)`)，以及難度選擇 (對戰最新一代或特定歷史世代的 `.nnue`)。
    *   **背景掛機貢獻**：閒置資源可透過勾選「協助訓練」在背景啟動 Self-play 迴圈 (每 50 局上傳)。
5.  **AI 訓練歷史回放介面 (AI Self-Play Viewer)**
    *   **資料來源**：提供介面拉取並觀看 AI 近期自我對弈的 100 局歷史棋譜，讓開發者與玩家能直觀審查 AI 的戰術邏輯與自我進化過程。
    *   **播放控制面板**：具備「開始播放 (預設每手 1 秒)」、「暫停播放」、「上一步」、「下一步」等標準覆盤功能。
    *   **人類可讀棋步 (Translation Display)**：必須實作解碼器，將底層的整數 `move_id` 即時還原為人類易讀的格式（如：`象 8,3 > 7,2 象吃俥`），並將每一步的詳細文字紀錄顯示於網頁旁的對局紀錄列表中。

## 二、 訓練資料與實際棋力的轉化機制 (使用者體驗設計)

本系統的核心目標是讓分散式算力最終能轉化為網頁上可見的「棋力提升」。

1.  **經驗資料變成 AI 的大腦**：
    網頁端產生的經驗資料，經由中央主機訓練微調後，打包成 `champion.nnue` 上傳至 Bucket。當人類打開網頁時，前端自動載入最新的權重，網頁版 AI 的評估眼光就已更新。
2.  **使用者感知與期望管理 (日更進化)**：
    系統採用「日更進化 (Nightly Build)」，確保每天都有新版本發布。雖然每天的實力提升 (Elo 增長) 對人類肉眼來說可能很微小，但日積月累會非常可觀。系統提供以下設計讓使用者體會連續進化：
    *   **勝率預測條 (Eval Bar) 的安定感**：隨著每日訓練疊加，使用者會發現 AI 在劣勢時勝率條不再劇烈震盪，能算出更遠的反殺步。
    *   **歷史世代對戰 (Version Select)**：UI 提供下拉選單選擇歷史版本（如初代 vs 最新日更版），透過跨世代交手，人類才能明確感受到幾個月下來帶來的戰術質變。

## 三、 錯誤處理與容錯機制 (Zero-Error Guarantee)

1.  **斷線重傳 (Retry & IndexedDB)**：若上傳時斷線，該批 50 局資料會暫存於 IndexedDB。網路恢復後自動補傳，算力不浪費。
2.  **壞軌過濾 (Checksum Validation)**：中央訓練機讀取 `.jsonl.gz` 時若發現檔案損毀，直接丟棄不引發例外中斷，保障系統穩定。
3.  **記憶體防爆**：瀏覽器 Web Worker 控制批次量，上傳後強制清空垃圾回收 (GC)，避免 Out of Memory。
