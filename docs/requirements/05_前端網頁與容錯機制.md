- URL：<https://hub-google.github.io/DarkChess-NNUE/>

- `.github/workflows/deploy_pages.yml`：手動部署 GitHub Pages；未重新啟用 push／workflow_run 自動部署。

## 二、正式 CPU 棋譜管線

正式自我對弈由 GitHub-hosted CPU Actions 的 Python `src/workers/self_play.py` 產生，並由 `upload_batch.py` 上傳 Hugging Face Dataset staging。瀏覽器**不**持有 Hugging Face Token，也**不**在背景大量上傳真實訓練資料。

- 每步計算最多 3 秒，使用小型 node budget，超出時只能採取合法公開資訊 fallback。
- 完整棋局會先寫入 runner 的 `output_data/*.jsonl.gz`，上傳時合併成批次。
- 若該 Worker 最終沒有任何完整合法棋局，上傳腳本須明確失敗；失敗工作可用 GitHub Artifact 保留復原材料。
- `self_play_trial.yml` 使用 CPU 真正完成 2 局、嚴格重播驗證合法終局並保存測試 Artifact；**不**接觸 HF 帳密／生產資料。

## 三、下一步的網頁改善（尚未完成）

1. 將 Python 正式棋規／搜尋重新實作為可在瀏覽器使用的同源 WASM/Rust 核心。
2. 為模型建立版本與正確性驗證，讓玩家對弈使用的 NNUE 與正式引擎一致。
3. 使用者可選擇計算額度、搜尋時間與歷史模型；以可測量的同等 CPU 預算比較棋力。
4. 若提供棋譜回放，應僅讀取公開、脫敏或專用示範資料，**不得在尚未結束的對局中暴露 `hid`**。
5. 由 Actions 自動產生訓練統計時應明確標註生成時間與資料來源，避免 0 筆的過時統計誤導玩家。

## 四、實驗／上線的驗收

- Python 規則、機率搜尋與棋譜驗證的 CI 先通過。
- 前端 `npm test` 與 `npm run build` 通過。
- Pages 部署成功後由實際瀏覽器手動測試翻牌、吃子、終局、模型載入；不能單憑 GitHub Actions 綠燈宣稱網頁完整驗收。
- 真正的新棋力只能透過配對 SPRT 與外部引擎測試驗證，不以「訓練輪次」或「網頁觀感」代替。
