# 02. 核心運算架構與搜尋引擎

為突破無 GPU 的限制，引擎底層必須極度輕量、高效。本核心引擎統一採用 **Python 搭配 Numba (@njit)** 開發，將底層邏輯 JIT 編譯為 C 語言等級的機器碼。

## 一、 盤面表示：位元棋盤 (Bitboard)
將 32 格的暗棋盤面映射為 32-bit 的整數陣列。因為暗棋剛好是 4x8=32 格，採用 32-bit 變數能在 TypeScript (Web Worker) 與 Python 中享受最極致的原生位元運算效能，無需動用 64-bit 或 `BigInt`。
*   **座標系統定義**：左上角為 0 (0x0)，右下角為 31。
*   **Bitboard 陣列結構**：系統需維護至少 16 個 32-bit 整數。包含各棋種位置 (帥, 雙仕, 雙相, 雙俥, 雙傌, 雙炮, 五兵，紅黑共 14 個 Bitboard)、`Occupied` (已被佔用的格子)、`Unflipped` (未翻開的暗子位置)。

## 二、 搜尋演算法：Star1 / Star2 (機率型 Alpha-Beta 剪枝)
捨棄 MCTS，改採針對機率節點 (Chance Nodes) 設計的 Alpha-Beta 剪枝，計算未翻開棋子的期望值。
*   **參數設定**：
    *   `MAX_SEARCH_DEPTH` (最大搜尋深度)：預設為 **12 層**（受中央主機調控，當遇到瓶頸時會自動加深以挖掘新戰術）。
    *   `TIME_LIMIT_MS` (每次行動思考時間限制)：掛機對弈預設為 **500 毫秒**，人機對弈可由使用者自訂 (1秒~無限)。
    *   `CHANCE_NODE_PRUNING_THRESHOLD`：設定預期勝率低於 5% 時不展開該機率分支。
    *   **自適應探索機制 (Boltzmann Exploration)**：為確保自我對弈產生的訓練資料具備多樣性，避免陷入局部最佳解：
        *   **前期探索 (前 N 步)**：由於 Alpha-Beta 回傳單一評估值，系統必須在搜尋樹的「根節點 (Root Node)」收集所有合法步的評估分數 $Q(s, a)$，並透過 **Softmax 函數轉換為機率分佈** $P(a) = \frac{e^{Q(s,a)/\tau}}{\sum e^{Q(s,b)/\tau}}$，再依此機率進行輪盤抽樣（$\tau$ 為動態溫度）。強迫 AI 在合理機率內嘗試不同戰術。
        *   **後期剝削 (N 步後)**：切換回完全決定性 ($\tau \to 0$) 的貪婪決策，展現真實棋力。

## 三、 評估函數：NNUE (Efficiently Updatable Neural Network)
當棋盤變動時，僅需更新受影響的網路節點，完美契合 CPU 的 SIMD 指令集。
*   **輸入特徵 (Input Feature)**：目前共 498 維，且只允許使用玩家可觀察的公開資訊：
    1.  **盤面特徵 (480 維)**：`32 格 * 15 種狀態 (14種明子 + 1種未翻開暗子) = 480`。讓神經網路能精確辨識暗子位置以迴避翻牌風險。
    2.  **未翻開牌庫特徵 (Bag State, 14 維)**：14 種棋子目前「尚未被翻出」的公開剩餘數量，除以初始數量正規化。搜尋不得讀取任何暗格的真實棋種。
    3.  **回合與和局特徵 (4 維)**：紅／黑輪到方 one-hot、60-ply 計數、目前局面重複次數。
*   **網路結構 (Topology)**：`Linear(498, 256) -> Clipped ReLU -> Linear(256, 32) -> Clipped ReLU -> Linear(32, 1)`。輸出統一代表**紅方視角**勝率 (-1.0 到 1.0)；紅方搜尋最大化，黑方搜尋最小化。
*   **量化 (Quantization)**：推論時必須將權重量化為 int16/int8 以使用 AVX2/WASM SIMD 運算。

## 四、 終局決策：殘局庫 (Endgame Tablebases)
預先計算並儲存 4~6 子的所有絕對勝負結果。搜尋樹觸碰到殘局庫條件時直接回傳分數，節省寶貴的運算深度。

## 五、 遊戲終止與防呆機制 (無限迴圈處理)
為防止分散式自我對弈時因長抓等情況陷入死循環，核心引擎內必須實作嚴格的判和規則：
*   **三次重複局面 (Three-fold repetition)**：歷史盤面狀態（包含未翻開牌庫與可見棋位）重複出現三次，立即判和。
*   **60 步防呆 (60-ply rule)**：若連續 60 步 (Ply) 沒有發生「吃子」或「翻牌」，立即判和。這能確保所有對局都能強制終止並回傳 `res: 0.0` (和局)，保護背景算力。
